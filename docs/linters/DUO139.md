# DUO139

This is a meta-diagnostic rather than a code rule. It is emitted when Dlint
cannot complete a scan because the shared resource budget has been exhausted,
or because the source file cannot be decoded with its declared encoding.

## Why this matters

Without an explicit budget, an extremely large file or a deeply nested
expression can consume all available memory while the parser or AST walker is
still running. Likewise, a file whose bytes do not match its declared encoding
can cause flake8 to fall back to a lossy decoding path in which AST-based
plugins never run. In both cases the file ends up with zero findings, which
looks identical to a clean file.

`DUO139` makes that condition visible: the scan is reported as incomplete
instead of clean, including which stage (`file`, `ast`, or `report`) exhausted
the budget.

## Shared budget

A single budget object is shared across all scan stages:

* **file** - charged one unit per source byte before parsing.
* **ast** - charged one unit per visited AST node.
* **report** - charged one unit per emitted finding.

The default limit is `10485760` units. Override it with
`--dlint-budget-limit` or the `dlint_budget_limit` flake8 config option. A
limit of `0` rejects every non-empty input at the file stage.

## Example

```
$ python -m flake8 --select=DUO --dlint-budget-limit=100 huge.py
huge.py:0:1: DUO139 scan incomplete: scan budget of 100 units exceeded during the file stage after 2780 units; results above may be partial
```

## Remediation

* Split or exclude genuinely huge generated files.
* Fix or remove incorrect encoding declarations and undecodable bytes.
* Raise `--dlint-budget-limit` only when the host has the memory to back it.
* Treat any `DUO139` result as a CI failure rather than a clean scan.
