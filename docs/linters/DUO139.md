# DUO139

This diagnostic is emitted when Dlint cannot complete a scan because a file
exhausts one of the shared resource budgets, or because its source cannot be
read or decoded. Unlike a clean result, a `DUO139` finding means the file was
**not fully analyzed** and the absence of other findings must not be treated
as evidence that the file is safe.

The file, AST, and report stages of every scan draw against a shared budget:

* **File budget** - the decoded source size, enforced while the file is read
  in fixed-size chunks so an oversized file is rejected before it can be
  buffered entirely in memory.
* **AST budget** - the number of nodes in the parsed tree, counted before any
  linter visits the tree.
* **Report budget** - the number of results emitted, so a pathological tree
  cannot produce an unbounded report.

## When it is reported

`DUO139` is reported, with a descriptive reason, when any of the following
occur:

* The source file exceeds `--dlint-max-file-bytes`.
* The parsed AST exceeds `--dlint-max-ast-nodes`.
* The number of findings exceeds `--dlint-max-results`.
* The source cannot be decoded as UTF-8.
* The parser or visitor runs out of memory.

Ordinary source files that stay within budget continue to be scanned
normally and report their usual findings; `DUO139` only appears for
incomplete scans.

## Configuration

The budgets can be tuned from the command line or flake8 configuration:

```
$ python -m flake8 --select=DUO \
    --dlint-max-file-bytes=5242880 \
    --dlint-max-ast-nodes=500000 \
    --dlint-max-results=100000 \
    path/to/code
```

## Resolution

* Split or exclude genuinely oversized generated or vendored files.
* Re-encode source files as UTF-8.
* If the file is legitimate and the host has capacity, raise the relevant
  budget explicitly rather than ignoring the result.
